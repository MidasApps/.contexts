**Goal:** Rename every Portuguese code identifier (variables, functions, properties, types, constants, components, file names) in `src/`, `app/`, `scripts/` to English, in dedicated behaviour-free `refactor` PRs, then lock the rule in with lint.

**Architecture:** A TS 6 LanguageService codemod (the `@typescript/typescript6` API the repo already ships for typescript-eslint) applies a reviewed, per-batch rename map: symbol renames with prefix/suffix preservation plus file renames with import rewriting. A literal/property-key fingerprint guard proves each batch changed no string literal and no serialized key. Batches go shared → features → pages/widgets → app → scripts, one PR each.

**Tech Stack (measured, `.contexts/engineering/stacks/VERSIONS.md` + `package.json`):** Node 24 (24.15 local), TypeScript 7.0.2 (`tsc`), `@typescript/typescript6` 6.0.2 → TS API 6.0.3 (programmatic API), Next 16.3.0, React 19.2.8, Zod 4.4.3, Vitest 4.1.10, ESLint 9.39.4 + typescript-eslint 8.61.1, pnpm 10.32.1.

## 1. Survey

### 1.1 How it was counted

Survey code: `docs/plans/2026-09-25-english-identifiers-survey/` (`scan.js`, `words.js`, `final.js`, `batches.js`). Nothing in the repo was modified.

1. **Files:** every `*.ts`, `*.tsx`, `*.mjs`, `*.js`, `*.cjs` under `src/`, `app/`, `scripts/`, plus `proxy.ts`. That is 1,115 files, or 1,102 after removing the 13 excluded files. Tests are included.
2. **Parsing:** real AST. Each file is parsed with `@typescript/typescript6` `createSourceFile`, and every `Identifier` node is visited, plus quoted property keys (`'foo': ...`). Comments, string literals, template text and JSX text are never looked at, so user-facing strings and test titles cannot show up in the counts.
3. **Splitting:** each identifier is split into words on camelCase, PascalCase, `_`, `-` and `.`. An identifier is Portuguese if at least one word is Portuguese.
4. **Lexicon:** a word counts as Portuguese if its accent-folded form is in a pt-BR lexicon (hunspell `dictionary-pt` lemmas ∪ the 50k pt-BR frequency list) **and** is not in `/usr/share/dict/words`. On top of that, about 220 hand-reviewed inflections the lemma list misses were added (`metricas`, `colapsada`, `autoraveis`...), plus about 90 PT/EN homographs that are Portuguese in this codebase (`valor`, `nome`, `campo`, `linha`, `pagina`, `estado`, `mes`, `para`, `ao`, `da`, `dos`...). About 110 English or tech tokens the pt corpus wrongly contains (`db`, `app`, `email`, `eval`, `demo`...) were removed, and words under 3 characters are ignored. Domain acronyms (`pdd`, `ltv`, `lgd`, `ead`, `ecl`, `vgv`, `ipca`, `selic`, `cdi`, `cnpj`, `cpf`, `cri`, `cra`, `fidc`, `mcmv`, `sbpe`, `iptu`...) are treated as glossary terms and are **not** counted as Portuguese.
5. **Classifying each occurrence:**
   - `A-datakey`: snake_case (`saldo_devedor`, `unidade_id`), dotted paths, or quoted keys that are not valid identifiers (`'Saldo Devedor com LTV > 80%'`, `'kpi-obra-previsto-acum'`). These are BigQuery columns, contract attribute paths, block/template ids and labels. Keep them.
   - `A-contract`: a property name that equals a data-contract entity or attribute name. Vocabulary is taken from `scripts/lib/{real-estate,vila-rosa}-schemas.mjs`, `scripts/seed-*contract*.mjs`, `scripts/seed-*-client.mjs` and `scripts/onboarding-lote-2026-09/atributos-*.mjs`, which gives 540 terms. Keep by default, and audit per occurrence.
   - `P-toolparam`: property names in the zod input schemas of LLM tools (`src/features/ai-agents/tools/**`, `src/features/report-authoring/tools/**`). These are persisted/LLM-facing. Keep.
   - `P-persisted`: hand-verified persisted fields (Firestore `blockMap` block fields and metric output-shape columns; see 1.4). Keep.
   - `B-prop`: other property names, whether declared, accessed, shorthand or JSX attributes. These are rename candidates, but each batch must audit them for serialization.
   - `C-local`: variables, functions, parameters, types, interfaces, classes, constants and imports that are never used as a property. Safe to rename.
6. **Units:** "names" means distinct identifier strings. "Occurrences" counts every declaration and reference. Per-area and per-module name counts are distinct *within* that scope, so they add up to more than the global unique total. Precision was spot-checked on a 1-in-12 sample of the rename list: remaining false positives are rare, and there are homograph misses in both directions (for example `real`, `total`, `base`, `media` and `grade` were left out on purpose). Treat the numbers as ±5%.

## 2. Tooling assessment

| Option | Available? | Verdict |
|---|---|---|
| `typescript@7.0.2` (`tsc`, `tsgo --lsp`) | yes | No programmatic API (exports only `version`). The LSP supports interactive F2 rename in an editor, but it cannot be scripted from the repo. |

| ts-morph / jscodeshift | not installed | New dependency, with a bundled TS 5.x. Not needed. |
| typescript-eslint `naming-convention` | installed (8.61.1) | Can deny regexes per selector, but it cannot tell persisted properties apart and needs case-bracketed alternations. Use a small local rule instead (Task 23). |

**Recommendation: a codemod, but with human-authored maps. Do not let it translate on its own.** Translation is a judgment call (for example `faixa` → `range` vs `band`, `casca` → `shell`, `régua` → `ruler`, `trilho` → `rail`, `recusa` → `refusal`), so each batch works in four steps:
1. the survey script emits a draft map (`name, kind, file, line, category`) for the module;
2. the implementer fills `to` using a shared `scripts/codemods/vocabulary.json` (PT → EN, the single source of truth, so the same word gets the same translation in every batch) and marks each `B-prop` as `persisted: false` after auditing it;
3. the codemod applies the map;
4. the fingerprint guard proves no literal or serialized key changed.

Do small batches, and fix up leftovers by hand (editor F2 with the TS 7 LSP is fine for those).

Make `@typescript/typescript6` an explicit `devDependency`, pinned exactly to `6.0.2`. The lockfile already contains it, so nothing new is downloaded. Record the justification required by development.md ("Dependências externas") in the PR and in the "Neste projeto" paragraph of `.contexts/engineering/stacks/language/typescript@7.md`. A fallback with no manifest change is `require.resolve('@typescript/typescript6', { paths: [require.resolve('@typescript-eslint/typescript-estree')] })`, but it is fragile.

`.mjs` files are **outside** the tsconfig program (`include` lists only `**/*.ts(x)`). For Tasks 20–22 the codemod adds `scripts/**/*.mjs` to the LanguageService root files (`allowJs` is already true), and verification relies on vitest plus `node --check`, because `tsc` does not cover them.

## 5. Risks and how each batch avoids behaviour change

| Risk | Mitigation |
|---|---|
| A persisted or serialized key gets renamed (Firestore, wire JSON, logs, tool I/O, storage) | Map entries with `kind: 'prop'` need audit evidence. Rename uses prefix/suffix text so external keys survive shorthand and destructuring. The fingerprint fails on any property-key change not in the map, and the keep-list in 1.6 is never put in a map. |
| Silent shadowing: new name captures an outer binding and `tsc` stays green | The codemod aborts when `to` is already visible in scope at any rename site (`getSymbolsInScope`). |
| String references the LS cannot see (`vi.spyOn(m, 'x')`, `vi.mock('path')`, `toHaveProperty('x')`, pick masks, `obj['x']`) | The codemod reports every `'oldName'` string hit, and the fingerprint allows literal changes only when they exactly map old → new. There are 528 `vi.mock`/`vi.spyOn` calls, but no snapshot tests and no runtime `Function.name` reliance (checked). |
| `.mjs` scripts outside `tsc` | The LS includes `.mjs` explicitly; add `node --check`, vitest, and `--dry-run` when credentials exist. |
| Prompt or LLM behaviour drift | Prompts, tool descriptions, schemas and result keys are literals or keep-list keys, which the fingerprint enforces. No eval run is needed for Tasks 1–22; any prompt edit is out of scope. |
| Conflicts with parallel work | One batch at a time, short branches, rebase before merge; the excluded files are never touched; Tasks 7–9 wait for the in-flight PR and Task 21 waits for PR #30. Announce the scope freeze in the PR. |
| Inconsistent translations across batches | `scripts/codemods/vocabulary.json` is the single source for translations; reviewers check new entries. |
| Huge diffs are hard to review | Batches stay at about 50–190 names. The codemod exception applies (processes/pull-requests.md). Reviewers read the map JSON, not every line, plus a spot check. |
| Hoisting break when converting `function` → `const` | Separate commit, only in touched files, keep `function` where it is used before its definition, and rely on the full tests plus `pnpm build`. |
| Stale docs and comments | `git grep -nw` old names across `docs/`, `.contexts/`, `adrs/` (non-Accepted), `CLAUDE.md` and comments, updated in the same commit. Accepted ADRs stay immutable. |
| Comments in mixed languages | Not translated; only references are updated. Comment-language consistency per module is a separate, optional doc pass. |
| Lexicon false positives or negatives | Numbers are ±5%, and the per-batch map review is the real gate. The lint rule allowlists and grows the lexicon. |
