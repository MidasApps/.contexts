Landing page UX/PM review completed and expanded on 2026-03-18.

**Key decisions:**
- Hero CTA should be "Agendar demonstracao" not "Acessar plataforma" (visitor doesn't have an account yet)
- Badge should position the product ("Plataforma para securitizadoras e gestores de CRI") not describe tech ("IA aplicada")
- H1 rewritten to pain-oriented: "Pare de descobrir problemas na carteira depois que ja aconteceram"
- Features section must be rewritten as benefits (outcomes, not capabilities) -- exact texts provided
- New sections needed: Dores (pain points), Social proof (logos/numbers), Antes/Depois (transformation)
- Section order: Hero > Social Proof > Dores > Mock > Benefits > Antes/Depois > IA > Compliance > Numbers > Multi-client > Security > CTA > Footer
- Footer needs LGPD compliance (Politica de Privacidade, Termos de Uso) and contact info
- Chat mock incoherence CRITICAL: projects 16.5% inadimplencia but KPIs show 0.09% -- recommended fix: change chat to show contract-level risk question instead
- Simulation section also incoherent: 16.8% base scenario vs 0.09% KPI -- must align
- BQML section recommended for removal (content absorbed into Features)
- TECH items rewritten for financial audience confidence (e.g., "IA com dados privados")

**Priority matrix:**
- P0: Chat mock incoherence, Footer LGPD, CTA swap to "Agendar demonstracao"
- P1: Hero rewrite, Dores section, Social proof
- P2: Features-as-benefits, Simulation data fix, Security items
- P3: Antes/Depois section, BQML removal, Section reordering

**Why:** C-level audience (CEOs, CFOs, CROs) buys outcomes not features. Current page describes what the product does without articulating why the visitor should care. Zero social proof is critical for B2B financial products.

**How to apply:** Use these guidelines when making any changes to LandingPage.tsx or creating marketing copy. Exact replacement texts are in the detailed review delivered to the user on 2026-03-18. Prioritize P0 items first.
