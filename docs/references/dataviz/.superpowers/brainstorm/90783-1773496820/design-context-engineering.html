Secao 3 de 5 — Como cada agente recebe seu contexto especializado

SQL Agent — Dicionario de Dados Completo

O system prompt do SQL Agent e o mais critico. Ele precisa conhecer profundamente o schema para gerar SQL correto.

System Prompt Structure — SQL Agent
BLOCO 1: Instrucoes de comportamento
- Gere apenas SELECT (nunca INSERT/UPDATE/DELETE)
- Sempre use LIMIT (default 100, max 1000)
- Use SAFE_DIVIDE para divisoes
- Formate moeda como BRL, datas como pt-BR
- Sempre inclua a query SQL na resposta
- Se a pergunta for ambigua, faca a query mais provavel e explique as premissas
BLOCO 2: Tabela CONTRATOS (~35 campos)
-- Tabela principal: dados de contratos por data-base
-- Chave: id_contrato + data_base_report
-- Granularidade: 1 row = 1 contrato em 1 data_base

id_contrato        STRING   -- Identificador unico do contrato
data_base_report   DATE     -- Data-base do relatorio (ultimo dia do mes)
projeto            STRING   -- Empreendimento (ex: "VIVA PARK")
documento          STRING   -- CPF/CNPJ do devedor
nome_cliente       STRING   -- Nome do devedor
proponent_type     STRING   -- "PF" ou "PJ"

valor_imovel       FLOAT64  -- Valor do imovel (R$)
ltv                FLOAT64  -- saldo_devedor / valor_imovel
faixa_ltv          STRING   -- "0-30%","30-50%",...,">100%"
rating_liquid      STRING   -- A(baixo risco) a H(default certo)
elegibilidade      STRING   -- "Elegivel" ou "Nao Elegivel"
dias_atraso        INTEGER  -- Dias em atraso (0=adimplente)

BLOCO 5: Formulas derivadas comuns
-- Use estas formulas para metricas calculadas:
inadimplencia_pct = SAFE_DIVIDE(SUM(valor_atraso), SUM(saldo_devedor)) * 100
ltv_medio = AVG(ltv)
over_90_pct = SAFE_DIVIDE(COUNTIF(dias_atraso > 90), COUNT(DISTINCT id_contrato))
desagio = SAFE_DIVIDE(SUM(pricing)-SUM(saldo_nominal), SUM(saldo_nominal)) * 100
pct_contratos = SAFE_DIVIDE(COUNT(*), SUM(COUNT(*)) OVER()) * 100

Estrategia de Contexto por Agente

Cada agente recebe apenas o contexto que precisa — nao o contexto completo do sistema.

SQL Agent
Estatico: Schema completo (3 tabelas, ~40 campos), formulas, regras SQL, valores categoricos
Dinamico: dataset, dateRange, projetos, advancedFilters
Tamanho estimado: ~3.000 tokens
Business Agent
Estatico: Glossario completo (~30 termos), escala ratings, regras Bacen, formulas de calculo
Dinamico: Nenhum (puro knowledge base)
Tamanho estimado: ~2.000 tokens
Dashboard Agent
Estatico: Instrucoes de interpretacao de KPIs, tendencias, alertas
Dinamico: buildAIContext() completo (indicadores, charts, filtros, pagina atual)
Tamanho estimado: ~4.000-8.000 tokens (varia com pagina)
Comparison Agent
Estatico: Metodologia de comparacao, polaridades de metricas, benchmarks
Dinamico: dataset, dateRange, comparePeriod
Tamanho estimado: ~1.500 tokens
External Agent
Estatico: Indicadores economicos relevantes, fontes confiaveis, correlacoes
Dinamico: Nenhum
Tamanho estimado: ~1.000 tokens
Export Agent
Estatico: Templates, regras de formatacao BRL/pt-BR
Dinamico: buildAIContext() (dados para exportar)
Tamanho estimado: ~1.500 tokens
Simulation Agent
Estatico: Modelos de simulacao (pricing, PDD, elegibilidade, LTV stress), formulas, parametros default, ranges aceitaveis
Dinamico: dataset, dateRange, projetos (para buscar baseline via execute_sql)
Tamanho estimado: ~2.500 tokens

Padrao de Injecao de Contexto

Como o contexto chega em cada agente
1. Arquivos estaticos Cada agente tem um arquivo de contexto em src/shared/config/agents/
Ex: sql-agent-context.ts exporta o schema como string template 2. Funcao factory buildAgentPrompt(agentId, dynamicContext)
Combina contexto estatico + dados dinamicos do request (dataset, filters, dashboard state) 3. Tool execute O orquestrador passa experimental_context com dataset/filters.
O async generator do sub-agente recebe via options.experimental_context 4. generateText Sub-agente chama generateText({ system: buildAgentPrompt(...), tools: agentTools })
Com modelo especifico e contexto isolado

Guardrails do SQL Agent

Validacao Pre-Execucao
- Rejeita qualquer statement que nao seja SELECT
- Injeta LIMIT 1000 se ausente
- Valida que tabela existe no dataset
- Timeout de 30 segundos
Permissoes
- Service account com role BigQuery Data Viewer
- Sem acesso a escrita (nao pode criar/alterar tabelas)
- Dataset scoped pelo cliente autenticado
Error Recovery
- Se SQL falha, sub-agente pode usar get_table_schema + retry
- Multi-step interno (stopWhen: stepCountIs(3))
- Erro legivel retornado ao orquestrador
