A — Tabs horizontais no header

Report Types como tabs abaixo do header principal, acima do sidebar. O sidebar mostra apenas as páginas do report type ativo. Hierarquia: Client → Report Type (tabs) → Pages (sidebar).

Prós

  • Report type sempre visível
  • Troca rápida com 1 clique
  • Sidebar permanece limpo e flat

Contras

  • Ocupa espaço vertical
  • Pode não escalar bem com 6+ tipos

B — Dropdown no sidebar

Report Type como seletor/dropdown dentro do sidebar, abaixo do client switcher. As páginas mudam dinamicamente quando troca o report type. Hierarquia: Client → Report Type (dropdown) → Pages (sidebar).

Prós

  • Não ocupa espaço vertical extra
  • Escala bem com muitos tipos
  • Mantém tudo na lateral

Contras

  • Report type fica "escondido"
  • Requer 2 cliques para trocar

C — Sidebar duplo (icon rail + pages)

Estilo VS Code/Discord: rail estreito à esquerda com ícones dos report types + sidebar principal com as páginas do tipo ativo. Hierarquia: Client (rail) → Report Type (rail) → Pages (sidebar).

Prós

  • Todos os report types sempre visíveis
  • Troca instantânea com 1 clique
  • Escala bem visualmente

Contras

  • Ocupa mais espaço horizontal
  • Mais complexo para implementar
  • Mobile precisa de adaptação maior
