## What was built

**Base (decision 0042).**

- `widgets/admin-nav`: `AdminPageFrame` (page `h1`, role gate), `AdminQuerySection` (skeleton,
  second-factor notice for 403 `MFA_REQUIRED`, no-access, error with request reference and retry),
  `useAdminSearch` (filters and page in the URL), `AdminOrganizationFilter`.

  and memory adapters).
- `useFormatMicroUsd`: cents through `{ amountMinor, currency }` and `formatMoney`; sub-cent trace

  `--chart-1…5`, with the same numbers in a visually hidden table.
- The admin navigation lists eleven areas, each gated by the platform permission its API checks.
  `platform-support` sees organizations, users, connectors, traces, logs and costs.
- `apps/web` keeps the single `admin/[[...section]]` route; `section-pages.tsx` maps the path to
  the shared view (composition only, decision 0041).

## API gaps (shown honestly in the UI, not faked)

1. No user search: `/admin/users` takes a user id.
2. No list of impersonation sessions: only the session started in the tab can be ended.
3. No `GET /v1/admin/organizations/{id}` and no members count for staff.
4. No `GET /v1/admin/agents`: the catalog is the core agent ids plus what an organization enabled.
5. No `/v1/admin/usage`: no cost by day or by model.
6. No way to clear an organization's flag override.
7. Evals: no dataset items or versions, no admin-started experiment, no filters, no server compare.
8. Traces: no time-range filter; trace cost is `null` until it is joined to the ledger.
9. Workflows: no admin run stream, so no step events; a staff cancel does not settle the approval
   request of a suspended run (it expires through the sweep).
10. Connectors: an organization is required, and staff cannot disable one.
11. Logs: web process only, local only; outside local the page links to Cloud Logging without a
    project id.
12. Prompt authors and run starters show as user ids; past eval results per scorer are not readable.

## Concerns

1. **Impersonation swaps only the Firebase user in the tab.** The staff server session cookie
   stays, so a reload returns to staff. The banner's "leave" is a full sign-out. Not exercised in a
   browser.
2. **Tripwire rate is always 0** from the API; the overview shows it as given.
3. **`/admin` dates use the browser time zone**, because there is no tenant node (decision 0042).
4. **Organizations are filtered on the client** over at most 2 000 rows.
5. **`src/**/lib/**` is not linted**: the ESLint config ignores `lib` folders (found by a fork).
   This covers `shared/lib/router` and `shared/lib/format`.
6. **Pause and resume of a schedule have no confirmation**; pausing a platform schedule stops a
   core job for every organization.
7. **Shared widgets read `admin.*` keys** (`traceViewer`, `costCharts`, `runTimeline`,
   `scheduleTable`); Task 14 should move them to a neutral namespace when `/settings` reuses them.
8. **Parallel load.** Under a full parallel run with other agents busy, typing-heavy tests timed
   out at 5 s; three admin test files now use 20 s. One unrelated test
   (`ProfilePreferencesView`) timed out once and passed on the rerun.
9. **`recharts` brings Redux Toolkit and D3** into the chart pages' bundle. The lockfile also
   re-resolved some `@mastra/*` peer suffixes on install.
10. **Backend not exercised against a running Mastra**; schedule tests use a fake
    `mastra.schedules`. The regenerated catalog and OpenAPI stay unstaged in main because they
    include SP3's uncommitted work.
11. **Some JSX-dense components exceed 50 lines** (forms, tables), within the rule's exception.
