## What was built

### Rust (`app/apps/desktop/src-tauri/`)

- `Cargo.toml`: `keyring = "=4.2.0"` (crates.io latest stable, measured 2026-09-30; default feature `v1` = Windows
  Credential Manager, macOS Keychain, Secret Service/zbus), `serde = "=1.0.229"` (derive; the version tauri already
  resolves), dev `serde_json = "=1.0.151"`. `Cargo.lock` updated by cargo (+keyring, keyring-core and the three
  native store crates with their deps).
- `src/secure_store.rs`: `Vault` trait, `KeyringVault` (service = bundle identifier, account `desktop-session`;
  missing entry → `None`, delete idempotent), `map_keyring_error` (variant only, never the payload: `BadEncoding`
  carries bytes), `validate_secret` (1–1024 bytes printable ASCII), `SecureStore` state and the commands
  `secure_store_get|set|delete` (`#[tauri::command(async)]`: keychain calls may block). Errors serialize as
  `{ "code": "SECURE_STORE_UNAVAILABLE" | "SECURE_STORE_FAILED" | "SECURE_STORE_INVALID_ARGUMENT" }`.
- `src/secure_store_tests.rs` (7 tests): store/replace/delete through a fake vault, argument validation before the
  keychain, failure pass-through, keyring error mapping, error JSON shape, plus an `#[ignore]` real OS keychain round
  trip under the test service `dev.core.desktop.cargo-test`.
- `src/lib.rs`: `setup` manages `SecureStore` with `KeyringVault(app.config().identifier)`; `invoke_handler`
  registers the three commands; a test pins the capability (window `main`, `core:default` + `allow-secure-store`,
  exactly three allowed commands).
- `permissions/secure-store.toml`: `allow-secure-store-get|set|delete` + set `allow-secure-store`. Hand-written
  (not `AppManifest::commands`, which would generate the same identifiers under `permissions/autogenerated`). With
  an app permission present, Tauri enforces the ACL on app commands (`has_app_acl_manifest`), so any future app
  command must be granted.
- `capabilities/default.json`: `["core:default", "allow-secure-store"]` for window `main`.

### TypeScript (`app/apps/desktop/src/`)

- `adapters/tauri-secure-store.ts`: `createTauriSecureStore({ invoke? })` over `@tauri-apps/api/core` `invoke`;
  native `SECURE_STORE_UNAVAILABLE` → port `SECURE_STORE_UNAVAILABLE`, anything else (invalid argument, ACL string,
  unknown) → `SECURE_STORE_FAILED`; the rejection value is never copied; a non-string `get` answer is refused.
- `adapters/desktop-session-record.schema.ts`: `DesktopSessionRecordSchema = { v: 1, sessionId, secret }` (contract
  `SessionIdSchema`, `DesktopSessionSecretSchema`), parse/serialize helpers.
- `adapters/desktop-session-bridge.ts`: `createDesktopSessionBridge({ apiBaseUrl, fetch, secureStore, getIdToken,
  reportError })` over the shared HTTP client + endpoint caller:
  - `establish`: `POST /v1/me/desktop-sessions` with the fresh ID token → store the record; on a store failure the
    new session is revoked; `SECURE_STORE_UNAVAILABLE` → sign-in continues without persistence (reported as
    `desktop_session_store`); other store failures fail the sign-in. A leftover record is revoked after the new one
    is stored.
  - `restore`: exchange (no Bearer) → store the rotated secret **before** returning the custom token; 401 → delete
    the record, `null`; transient errors → throw, record kept; unreadable record → deleted + reported.
  - `end`: `DELETE /v1/me/sessions/{sessionId}` with the current ID token (best effort, reported), then always delete
    the keychain entry (an unavailable store is ignored).
- `app/create-desktop-runtime.ts`: auth built first; `sessionBridge = createDesktopSessionBridge(...)` with
  `selectSecureStore({ scope: args.scope ?? globalThis, native: () => createTauriSecureStore() })`; new optional
  `scope` arg (tests). `adapters/process-session-bridge.ts` deleted (untracked from Task 20, no other user).
- `adapters/desktop-secure-store.ts`: doc comment updated.
- `package.json`: `@core/contracts: workspace:*` (the bridge uses the SP1 endpoint descriptors). `pnpm install
  --offline` updated only the `apps/desktop` importer in `pnpm-lock.yaml`.
- Tests: `tauri-secure-store.test.ts` (4), `desktop-session-bridge.test.ts` (11, fake SP1 server with rotating
  secrets and the real memory store), `app/desktop-app.test.tsx` +2 integration tests (real bridge + real
  `createTauriSecureStore` over a fake `window.__TAURI_INTERNALS__`: a keychain record from a "previous run"
  resumes into the user area, the exchange has no `authorization` header, and the keychain then holds the rotated
  secret; an empty keychain starts signed out without calling the exchange).
- `README.md` (session, secure store, ACL, Credential Manager entry, cargo test commands) and decision 0017
  ("Outcome of SP2 Task 21").
