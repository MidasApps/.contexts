### Harness (Task 22)

- **Own stack, apart from `pnpm dev`.** `app/firebase.e2e.json`: project **`demo-core-e2e`** (own hub locator and
  data), Auth 9391, Firestore 8391 (websocket 9392), hub 4491, logging 4591, no UI. `scripts/e2e.ts` = root
  **`pnpm test:e2e`**: builds the e2e env (`scripts/src/e2e/e2e-env.ts`, unit-tested: ports read from
  `firebase.e2e.json`, no port shared with the dev emulators, 3000 refused), then
  `firebase --config firebase.e2e.json emulators:exec --project demo-core-e2e --only auth,firestore
  "pnpm exec turbo run test:e2e --filter=@core/web --filter=@core/desktop --env-mode=loose --concurrency=1"`.
  The env replaces every target of `.env.local` (emulator hosts, `NEXT_PUBLIC_*`, `VITE_*`, CORS, app URL,
  `AI_MODE=fake`, `DATABASE_URL` of the compose file; Storage/Pub/Sub point at unused ports so nothing reaches the dev
  emulators). `pnpm test:e2e -- <command>` runs another command inside the same stack.
  Ports: `E2E_WEB_PORT` (default 3100), `E2E_DESKTOP_PORT` (default 1420).
- **turbo.json:** `build` keyed on `NEXT_PUBLIC_*`/`VITE_*` (an e2e build and a dev build are different outputs);
  `test:e2e` comment; `@core/desktop#test:e2e` also depends on `@core/web#build`. `--concurrency=1` because both
  configs start `next start` on the e2e web port; the filter because turbo otherwise runs `build` of packages that have
  no `test:e2e` (functions, mastra — and `apps/functions/lib` is locked while another agent's emulator runs it).
- **`packages/e2e` (`@core/e2e`, new):** the shared harness, so the desktop config does not import the web app
  (boundaries: apps never import each other). `e2e-env.ts` (Zod-validated e2e env, fails with "run through
  `pnpm test:e2e`", loopback/`demo-*` only; opt-ins `E2E_REUSE_SERVERS=1` for local iteration and `E2E_SCREENSHOTS=1`
  for evidence screenshots), `web-server.ts`
  (`next start` in the web folder, reuse off by default), `emulator.ts` (Auth Emulator REST: upsert verified users,
  password sign-in for seeding, phone MFA enrollment, SMS code **by `sessionInfo`** so parallel sign-ins never read
  each other's code), `api.ts` (`/v1` Bearer client), `seed-users.ts` (idempotent world, below), `sign-in.ts` (UI
  sign-in, SMS challenge, phone-sheet-aware `showSidebar`/`closeSidebarSheet`/`accountMenu`), `axe.ts`
  (`wcag2a/2aa/21a/21aa/22aa`, waits for running animations, violations listed with axe's summary), `test.ts` (`createE2eTest({ authDir })`:
  `env`, `world`, `emulator`, `ownerApi`, `createUser`). `boundaries.js` registers element `e2e` (app → e2e allowed;
  e2e → only itself) with two fixture tests.
- **Seeded world** (`seedWorld`, idempotent; the setup project writes `e2e/.auth/world.json`): `owner@demo.local`
  (same account/password as `pnpm seed:local`), "Alpha Org" (projects "Alpha Launch" + "Alpha Growth", unit

also failed dark blue/violet/destructive over `#262626`), and `globals.css` got new text tokens: light blue `#0057d4`,

`#b48cff`, destructive-text `#ff7778`. Raw accents unchanged. Recorded in decision 0014 ("Outcome of SP2 Tasks
22–23"). A stale desktop `dist` built before the change reproduced the 4.43–4.46 failures (RED), the rebuilt one passed.

## Concerns

1. **No commits** (permission).
2. **Desktop port on this machine:** 1420 is held by another agent's `tauri dev` Vite, so my runs used
   `E2E_DESKTOP_PORT=1421` (CORS and `VITE_API_URL` follow). CI and a clean machine use the defaults 3100/1420.
3. **`/admin` for non-staff is the not-found UI with HTTP 200** (as reported in Task 19); the spec asserts the UI.
4. **Invitation links have no locale** (`<app>/invite#token=…`); the proxy redirects to `/pt-BR/invite` and the
   fragment survives, so it works, but the link could carry the inviter's locale (follow-up for the web).
5. **Profile nav prefetch 404s:** on `/profile/*` the RSC prefetch of the sibling sections (`?_rsc=`) answers 404 in
   the browser console, although the pages render on navigation (seen while exploring; not a test failure). Worth a
   look in the web routing (Task 19 area).
6. **Phone sheet stays open after switching organization/project** and re-renders when the new claims arrive; the
   specs close it explicitly. A UX follow-up (close the sheet on context switch).
7. **Currency preference is display-only by SP1 design** (the example page shows the node currency), so the profile
   test proves the currency is saved and the time zone reformats the example page.
8. **Load sensitivity:** with all browser projects in parallel on this shared machine, cold session restores took
   longer than the default 10 s expect timeout; the config caps workers at 4 and the a11y settle waits 30 s. The first
   `/v1` call of a cold `next start` took more than 15 s once, so seeding calls allow 60 s.
9. `settings` invite journey runs on Chromium only (Playwright grants clipboard permissions only there).
10. `pnpm test:e2e -- <command>` goes through the shell of `firebase emulators:exec` (cmd on Windows);
    `joinCommandArgs` double-quotes arguments with spaces or operators (checked with `-g "SMS code from|keeps it
    after a reload"`, which selects exactly those two tests).
