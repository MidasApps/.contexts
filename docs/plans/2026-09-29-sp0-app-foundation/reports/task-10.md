## What was built

### Web CORS (`@core/services` + `apps/web`)

- `services/shared/http/cors.ts` (pure, 18 tests):
  - `CorsOriginListSchema`: comma list → `scheme://host[:port]` origins only (no path, query, userinfo, trailing slash); `*` rejected; empty = CORS off;
  - `createCorsPolicy`, `isCorsPreflight`, `preflightResponse` (204; allowed origin gets allow-origin/methods `GET, POST, PUT, PATCH, DELETE`/headers `authorization, content-type, idempotency-key, x-request-id`/max-age 600; disallowed origin gets no `access-control-*`), `applyCorsHeaders` (echo origin + expose `x-request-id`; `Vary: Origin` always). Never `allow-credentials`.
- `apps/web/src/http/create-proxy.ts`: `createProxy({ corsPolicy })`; CORS only on `/v1` and `/v1/*`; preflights answered in the proxy with `x-request-id`. `src/proxy.ts` wires it from `env.CORS_ALLOWED_ORIGINS`. The old `proxy.test.ts` moved to `http/create-proxy.test.ts` (+4 CORS tests).
- `web-env.schema.ts`: `CORS_ALLOWED_ORIGINS` optional; `local` defaults to `http://localhost:1420,tauri://localhost,http://tauri.localhost`; **outside local it is required** (`InvalidEnvError` `CORS_ALLOWED_ORIGINS (REQUIRED)`), so dev origins never ship silently. `.env.example` documents it.

## Deviations and notes

- **`@tauri-apps/api`** is used only for `isTauri()`, which makes the Tauri-vs-browser evidence visible.
- **`pnpm -F desktop build` is Vite only.** Rust builds are opt-in (`tauri:build`); they take 5–10 min and 5 GB of `target/`, too heavy for `turbo build`/CI by default.
- **Base CSP keeps `http://localhost:3000`** (brief); other origins come only through the generated merge patch.
- **Web now needs `CORS_ALLOWED_ORIGINS` outside local** (new required variable for dev/staging/prod deploys).
- **Gitignore bug from Task 1:** `src-tauri/target/` in `app/.gitignore` was anchored to `app/` and did not match `apps/desktop/src-tauri/target`; fixed with `**/`.
- Two `Vary` headers reach the client on `/v1` (ours `Origin` + Next's `rsc, ...`); HTTP treats them as one combined list.
- pnpm re-resolved some peer suffixes in the lockfile (`eslint@9.39.5(supports-color@7.2.0)` → `eslint@9.39.5`, vite peer variants) when the desktop importer was added; versions are unchanged.
