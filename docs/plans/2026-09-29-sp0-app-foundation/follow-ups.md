# SP0 follow-ups

These are open items found during SP0 that are deliberately left for later. Each entry names its source and the subproject that owns it. The SP0 summary (Task 12) and SP3 planning read this list.

| # | Item | Why it matters | Owner | Source |
|---|---|---|---|---|
| 1 | **PostgresStore auto-init in remote environments.** Use `disableInit: true` at runtime, add an explicit `storage.init()` migration step in deploy under a DDL-capable role, and give the runtime a least-privilege role (DML only on schema `mastra`). | At boot, `PostgresStore` creates and alters 43 `mastra_*` tables, so the runtime user needs DDL today. | SP3 | Task 8 (`reports/spike-mastra.md`) |
| 2 | **`mastra build` runs a nested `pnpm install`** in `.mastra/output`. It resolves the exact versions the deployer writes, so our lockfile is bypassed, and it needs registry access during the image build. Options: vendor from the workspace store, pin with an output lockfile, or build with network policy plus audit. | This is a supply-chain and reproducibility gap in the Mastra image. | SP3 / deploy | Task 8 |
| 3 | **Cloud SQL socket DSN is rejected** by the `DATABASE_URL` check in `ServicesEnvSchema`. That check is `z.url` with protocol `postgres(ql)`, so it fails for a host-less socket form such as `postgresql://user@/db?host=/cloudsql/...`. Support the socket form or the Cloud SQL connector config explicitly. | Cloud Run with Cloud SQL uses the unix socket or the connector (spec §16.3). | SP3 | Task 8 review |
| 4 | **The Functions deploy manifest has no lockfile.** `apps/functions/lib/package.json` pins `firebase-functions` and `firebase-admin` exactly, but Cloud Build's `npm install` resolves their transitive dependencies fresh. Generate `lib/package-lock.json` in `build.ts` (for example `npm install --package-lock-only` against the manifest), or document an alternative such as vendoring. | This **blocks the first real deploy**: it is a reproducibility and supply-chain gap. | SP deploy (before the first remote Functions deploy) | Task 9 review |
| 5 | **Done in Task 11** (`scripts/dev.ts`: one build, then an esbuild watch, before the emulators). **`pnpm dev` must build Functions before the emulator starts,** and rebuild on change. The emulator loads `apps/functions/lib` at start and watches it, so run `node build.ts` first and then keep an esbuild watch (or `turbo watch build --filter=@core/functions`) next to `firebase emulators:start`. | Without it, the emulator fails with "lib/index.js does not exist" on a fresh clone, or serves stale code. | Task 11 | Task 9 review |
| 6 | **No `desktop-check` CI job.** A `cargo check` on ubuntu needs the Tauri apt deps (`libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`, `libxdo-dev`, `libssl-dev`), a built `dist/` (so `vite build` with an https `VITE_API_URL`), and about 4 min cold. It was not added because it could not be verified on Linux here. | Rust regressions in `src-tauri` are caught only locally. | SP2 | Task 11 |
| 7 | **Windows Ctrl+C in `pnpm dev` takes about a minute.** turbo runs each task through `pnpm.cmd`, cmd asks "Terminate batch job (Y/N)?" with no stdin to answer, and turbo force-kills web and Mastra after its graceful timeout. Nothing is orphaned (verified), it is only slow. Options: spawn `next dev`/`mastra dev` directly from `scripts/dev.ts` instead of through turbo, or a turbo shutdown-timeout setting if one exists. | Developer experience on Windows. | DX, any SP | Task 11 |
| 8 | **Pub/Sub emulator orphan (firebase-tools 15.32.0, Windows).** The CLI starts it through a shell; on stop the shell dies and its `java.exe` keeps port 8085. `scripts/dev.ts` snapshots the emulator process tree once everything is up and kills survivors after shutdown (`src/dev/process-tree.ts`). `pnpm test:emulators` does not start Pub/Sub, so it is not affected. | Without the workaround, port 8085 stays held after `pnpm dev` stops, which can block the next start. | upstream / DX | Task 11 |
| 9 | **CI has no pnpm store cache** and runs emulator tests on Node 26, while Functions deploy on nodejs24 (Task 9 concern 5). Add `actions/cache` on the pnpm store keyed by the lockfile, and a Node 24 job for `@core/functions` emulator tests. | CI time and runtime parity. | SP deploy | Task 11 |
| 10 | **`pnpm audit` reports 2 moderate advisories** (none high or critical, so CI passes). Review them and record a decision. | Supply chain hygiene (`rules/security.md` §9). | SP1 | Task 11 |
| 11 | **`WEB_PORT` does not move the URLs that point at web.** `NEXT_PUBLIC_APP_URL`, `MASTRA_CORS_ORIGINS` and the desktop `VITE_API_URL` default to port 3000; a developer on another port updates them by hand (documented in `.env.example` and the desktop README). | Surprising when port 3000 is taken. | DX | Task 11 |
