## Task 13 — sessions (`a9c2d03`)

Under `packages/services/src/services/identity/`:

- Domain: `session-secret.ts` (32 random bytes → 43-char base64url, `sha256` hex, `secretHashesMatch` =
  `timingSafeEqual` over the hex digests), `user-agent.ts` (browser + OS family only, e.g. `Firefox on Windows`; the
  raw string is never stored), `session-record.schema.ts` (the stored `sessions/{id}` shape: `cookieHash` or
  `secretHash`, `previousSecretHashes` (last 10, for reuse detection), `mfa`, `expiresAt`, `lastSeenAt`,
  `revokedAt`), `errors/session-errors.ts`.
- Ports: `SessionRepository`, `SessionCookieIssuer` (verify ID token with revocation + `auth_time` + MFA, create
  cookie, `verifySessionCookie(cookie, true)`), `CustomTokenIssuer`, and **`AuthUserAdmin`** (not in the plan's file
  list: `getState` (disabled, `tokensValidAfterTime`), `revokeRefreshTokens`, `createAccount`, `disable`; shared with
  the device vertical). Firebase/Firestore adapters, in-memory repository and `fake-firebase-auth.ts` for unit tests.
- Use cases: `create-web-session` (auth_time ≤ 5 min → else `RECENT_SIGN_IN_REQUIRED`; `SESSION_MAX_AGE_DAYS` ×
  86 400 000 ms), `exchange-web-session` (custom token `{ smfa, sessionId }`), `sign-out-web-session`,
  `require-web-session`, `require-platform-staff-session` (active staff doc + active user + MFA recorded on the
  session), `list-sessions`, `revoke-session` (own only, else 404; idempotent), `revoke-all-sessions`
  (`revokeRefreshTokens` first, then every open record), `create-desktop-session`, `exchange-desktop-session`
  (hash lookup → open desktop session → Auth account enabled and `createdAt > tokensValidAfterTime` → rotation in a
  transaction that re-checks the stored hash; sliding `DESKTOP_SESSION_MAX_AGE_DAYS`; a rotated secret presented
  again revokes the session and audits `DESKTOP_SESSION_REUSE_DETECTED` (platform log, actor `system`)). Session
  writes are refused under impersonation (403). Session audits go to `platform-audit-logs` (no tenant).
- Driving: `session-actions.ts` — `makeSessionActions({ sessions, appUrl, logger })` → `createSession(input, ctx)`,
  `exchangeSession(ctx)`, `signOut(ctx)`, each `{ ok: true, data } | { ok: false, error: { code, message, details?,
  requestId } }`, with `ctx = { cookies: CookieJar, origin, userAgent?, requestId? }`; the `Origin` must equal
  `NEXT_PUBLIC_APP_URL`'s origin (a server without it refuses every action); `CookieJar = { get, set(name, value,
  { maxAgeSeconds }), delete }`; `SESSION_COOKIE_NAME = "__session"`. `session-guards.ts` — `requireWebSession(cookies)`
  → `{ kind: "session", principal, sessionId } | { kind: "redirect" }`, `requirePlatformStaffSession(cookies)` →
  `{ kind: "staff", principal, sessionId, role } | { kind: "redirect" } | { kind: "not-found" }` (missing MFA is
  `not-found` too). `sessions-routes.ts` (5 endpoints). `CoreServer` gains `sessions`, `sessionActions`,
  `sessionGuards`; `createCoreServer` env accepts `SESSION_MAX_AGE_DAYS`, `DESKTOP_SESSION_MAX_AGE_DAYS`.
- Web: route files `v1/me/sessions`, `v1/me/sessions/[sessionId]`, `v1/me/sessions/revoke-all`,
  `v1/me/desktop-sessions`, `v1/desktop-sessions/exchange`; `apps/web/src/server/session-cookie-jar.ts`
  (`createSessionCookieJar()` over Next `cookies()`) with the flags in `session-cookie-options.ts` (`HttpOnly`,
  `SameSite=Lax`, `Path=/`, `Secure` except `APP_ENV=local` on an `http://` app URL).
- **Controller addition — `SessionSummary.current`:** `SessionSummarySchema` gains `current: boolean` (additive);
  `UserPrincipalSchema` gains optional `sessionId`, mapped from the developer claim `sessionId` of a custom-token
  sign-in only (our exchanges set it); `GET /v1/me/sessions` marks the session whose exchange minted the calling token.
  Catalog and OpenAPI regenerated.
- Index: `sessions uid+revokedAt+createdAt desc`; `cookieHash`, `secretHash`, `previousSecretHashes` are automatic
  single-field indexes.

## Deviations and concerns

1. **TDD order.** Red first for the domain tests, the session/API key/device use-case tests, the `current` flag, the
   cookie options, the audit actions and the error code. `session-actions.test.ts`, the route unit test for the
   redeem lockout and the three emulator tests were written after their code.
2. **The `device` system role holds no core permission** (`core-permissions.ts`), so a device granted only `device`
   gets 404 from `GET /v1/me/context` (it needs `core.organization.read`). The emulator test activates the device
   with `viewer`. Modules are expected to give `device` their own permissions; if the core should let every device
   read its context, `core.organization.read` needs `device` in its default roles (contract change, not made).
3. **Redeem does not re-check the admin's rights** (the invitation acceptance does); the activation lives 10 minutes.
4. **`AuthUserAdmin` port and `prepareRevokeAllGrants`/`checkGrantable` on `AccessServices`** are additions beyond
   the plan's file list; the device grant logic stays in the access context.
5. **`tokensValidAfterTime` has second granularity** (Firebase floors it); a session created in the same second
   before a revoke passes that check, but revoke-all also marks every record revoked, so it is refused anyway.
6. **Generated files.** `docs/openapi/v1.yaml` and `docs/catalog/**` blobs were generated in the scratch worktree
   and staged index-only; the main working tree was regenerated and holds the union with SP2's module contracts
   (unstaged). SP2's hunks in `composition.ts`, `services/src/index.ts` and `audit-action.schema.ts` stay uncommitted
   (composition.ts was hand-merged: HEAD + SP2's module-settings hunks).
7. **Concurrent agents.** SP3 committed `36a8b9b…f1615dd` meanwhile; my commits were rebased in the scratch worktree
   (no conflicts) and replayed through the main index with identical trees.
8. `firestore.rules` untouched (Task 19): `sessions`, `api-keys`, `devices`, `device-activations` are denied by default.
