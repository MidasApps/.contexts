## Fix (a): a run without `X-Conversation-Id` (follow-up #24)

- **Auto-create, not 400.** These requests get a new conversation id from the context middleware
  when they carry no `X-Conversation-Id`:
  - `POST <prefix>/agents/<id>/generate|stream`;
  - MCP server calls (`<prefix>/mcp/<id>/mcp`).

  The id is 20 characters of the Firestore alphabet. The middleware writes it as the memory
  thread under the caller's resource (`tenantId:uid`), and Mastra creates the thread for that
  resource. The id is returned in `X-Conversation-Id`, set before `next()` so streamed answers
  carry it too. The gateway exposes it as `GatewayStream.conversationId`.
- Approval, decline and memory routes never get a new thread.
- A malformed forwarded id (outside `[A-Za-z0-9_-]{1,128}`) answers 400. Before, it was dropped
  silently and the run failed with 500.
- Recorded as a decision 0019 amendment.

## Fix (b): SP1 approvals bound, command idempotency (follow-up #26)

- **Port.** `ApprovalPort.requestApproval` now carries `requestId`.
  - It maps to SP1 `requestApproval({ principal, input: { node, permission, action: { kind:
    "agent-command", input: <AgentApprovalRequest>, summary } }, requestId })`.
  - `ok: false` rejects with SP1's code, so the tool answers `APPROVAL_UNAVAILABLE`.
  - `approvalId` is `data.id`.
  - A platform node is refused before SP1 is called.
- **Handler placement (deviation).** The `agent-command` handler lives in `@core/services`
  (`services/agents/application/commands/`), not in `@core/agents`. Approvals are decided in
  `/v1` (`apps/web`), and the web cannot import the agent runtime.
  - `registerAgentCommandApprovals` registers it in `apps/web` (`runtime-routes.ts`), where the
    command runs, and in `apps/mastra`, where SP1 checks that the kind exists.
  - The call is idempotent per registry.
- **Handler checks.** Each refusal is a SCREAMING_SNAKE code that SP1 audits on
  `APPROVAL_FAILED`.

  | Check | Refusal code |
  |---|---|
  | The requester still resolves | `REQUESTER_UNAVAILABLE` |
  | The requester is the uid the action names | `REQUESTER_MISMATCH` |
  | The action's tenant equals the approved request's | `TENANT_MISMATCH` |
  | The action's permission equals the approved request's, and the executor's | `PERMISSION_MISMATCH` |
  | An executor exists for the command | `UNKNOWN_COMMAND` |
  | SP1 re-authorizes the requester at the request's node | `REQUESTER_FORBIDDEN` |
  | The input matches the executor schema | `COMMAND_INPUT_INVALID` |
  | The use case accepts the command | `COMMAND_REFUSED` |

- **Executors.** Today the only one is `tenancy.CreateProjectInput` → SP1 `createProject`. It
  duplicates the agent tool's definition until Task 19 derives commands from contracts.
- **Idempotency.** SP1's Firestore `IdempotencyStore` (decision 0009) is reused, with record id
  `sha256("tenant:<t>:agent-command:<commandId>:<runId:toolCallId>")`.
  - The tool pipeline routes every mutation through the new `commands` port. The approval
    handler uses the same records.
  - A replay returns the stored result.
  - The error codes are `IDEMPOTENCY_KEY_REUSED`, `COMMAND_IN_PROGRESS` and
    `IDEMPOTENCY_UNAVAILABLE` (fail-closed).
- Recorded as a decision 0025 amendment.

## Task 23: Firecrawl web tools

- **SDK.** `firecrawl` 4.42.1 (MIT), not `@mendable/firecrawl-js`. It is the same SDK, and
  decision 0027 keeps one name.
  - The key and API URL are always passed explicitly, so the SDK never reads `process.env`.
  - 12 s timeout, one retry.
- **Tools.** Both are core read tools with permission `core.web-tools.use`.
  - `web.search` returns 1–5 results with https addresses only.
  - `web.scrape` returns Markdown of the main content, capped at 20 000 characters with a
    `truncated` flag.
  - Output is wrapped as `<untrusted_web_content source="…">`, and a forged closing tag in the
    page text is escaped.
  - The web agent offers them only with `agent-settings.webTools.firecrawl` **and** a resolvable
    key.
- **Keys.** The tenant's own `firecrawl-<tenantId>` in the secret store comes first, then
  `FIRECRAWL_API_KEY`. A self-hosted `FIRECRAWL_API_URL` may run without a key, and it must be
  https outside local.
- **SSRF.** The guard checks the requested URL before Firecrawl is called, and the final address
  Firecrawl reports after its redirects. This matters when Firecrawl is self-hosted in our
  network.
- **Knowledge URL sources.** The `webContent` port is bound to the same clients and guard
  (500 000-character bound). URL ingestion needs a key but not the chat opt-in.
- **Fake mode.** Fixture pages live on `docs.example.com`. The guard's DNS resolves only the
  fixture hosts to a public test address, so private targets are still refused. The fake web
  agent searches, and a real-mode smoke test skips without a key.
- **Not done.** The PDF `parsePdf` hook is not wired to Firecrawl `parse`: it would send tenant
  documents to a third party, and `compliance.md` is still a template.
- Recorded as a decision 0027 amendment.

## Task 24: core MCP server and `/v1/mcp`

- **Server.** `MCPServer` `core` exposes:
  - the tools `listEntities`, `describeEntity`, `searchKnowledge` and `querySemanticSql`, through
    the core pipeline with caller key `mcp` and its own ceiling;
  - `ask_assistant`;
  - `catalog://<id>` resources filtered by the caller's permissions.

  `requestState.key` is `MCP_REQUEST_STATE_KEY`. No mutation tool is exposed.
- **Context bridge.** `MCPServer` builds an empty request context per MCP request.
  - `server.mcpOptions.setRequestAuth` copies the verified snapshot into `req.auth.extra`.
  - The server's `mapAuthInfoToUser` writes it back with `writeAgentContext`.
  - Without this bridge the tests fail: the tools answer `CONTEXT_MISSING` and the supervisor's
    `requestContextSchema` fails.
- **Route.** `POST /v1/mcp?organizationId=…`.
  - Users must name the organization, like `GET /v1/me/context`. A missing one answers 400.
  - An API key acts in its own organization, and another one is 403.
  - The route checks `core.mcp.use`, then the gateway proxies to `/api/mcp/core/mcp`.
  - Rate limit `mcp-call`: 60 per minute per principal.
- **Sessions (decision).** `@mastra/mcp` 2.x serves MCP 2026-07-28, which is stateless and never
  issues `Mcp-Session-Id`. Nothing needs instance affinity.
  - The gateway forwards only the MCP transport headers: `Accept`, `Mcp-Method`, `Mcp-Name`,
    `Mcp-Param-*`, `MCP-Protocol-Version`, `Mcp-Session-Id` and `Last-Event-ID`.
  - The SDK requires the first three, so a body-only proxy would have failed with real clients.
  - It passes back the status (a 202 has no body), `Content-Type` (JSON or SSE),
    `Mcp-Session-Id`, `MCP-Protocol-Version` and `X-Conversation-Id`.
  - Only POST is served.
- New contract `agents.callMcp` in `@core/contracts`. OpenAPI was regenerated.
- Recorded as a decision 0027 amendment.

  which has 7 high advisories. The override `"firecrawl>axios": 1.20.0` fixes it.
  - The deployer's nested install ignored the override, so the pin check reported the drift.
    That is why step (0) exists.
  - The workspace audit is also back to 0 high.
- **Image.** `.dockerignore` excluded `docs/`, so the image build could not resolve the inlined
  `docs/catalog/catalog.ai.json`. It now allows that one file.
- Recorded as a decision 0023 amendment. Follow-up #2 is marked done.

## Deviations and concerns

1. **Handler placement.** The `agent-command` handler lives in `@core/services`, not
   `@core/agents`, because the web decides approvals. The core command is defined twice (agent
   tool and executor) until Task 19.
2. **The organization is in the query.** `/v1/mcp` takes `?organizationId=`, and it is required
   for users. MCP clients configure it in the URL.
3. **MCP protocol errors with a 4xx status reach clients as the `/v1` envelope**, not as
   JSON-RPC (status-only mapping, follow-up 12d). Tool errors are unaffected (200 with
   `isError`).
4. **`replayed` audit metadata stays on the port.** SP1's audit allowlist has no `replayed` key,
   and I did not change the SP2-dirty audit contract.
5. **The Firecrawl PDF parse is not wired.** It is a compliance decision (see Task 23).
6. **Environment incident.** Once, the worktree's `node_modules` lost sibling links (vitest,
   eslintrc→ajv) around the Task 25 build. A clean `pnpm install --force` followed by a full
   build with the output reinstall kept the workspace intact. I found no cause in my scripts.
   The output install runs in its own workspace root (`.mastra/output`).
7. **Flaky under load.** The first test of `create-runtime-ports.test.ts` took 7.9 s once and
   failed. It passed on rerun.
8. **Follow-up numbering.**
   - SP2 holds uncommitted follow-up rows 32–35, so my new row is **#36**: drop the `axios`
     override and the firecrawl release-age exclusion.
   - #2, #24 and #26 are marked done.
9. **Pub/Sub IAM.** `gcp` Pub/Sub needs the Mastra service account to hold publisher and
   subscriber roles on the adapter's topics and subscriptions. This is a deploy step, not
   verified against a real project.
